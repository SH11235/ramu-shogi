# 対話解析の状態管理

`createAnalysisController` は専有する `EngineClient` の操作を直列化する。
画面側は対象局面を `select`、主操作を `start` / `pause` に接続する。
同じ局面・履歴の再開状態があれば `start` は `analysis.resume` を呼ぶ。

- `prepare` は初回開始時だけ呼ぶ。ここで初期化と NNUE・Threads・Hash・MultiPV を適用する。
- 設定変更時は既存 controller の `dispose` を待ってから作り直す。通常探索・全体解析と client を同時使用しない。
- 選択だけでは起動しない。開始後の局面移動は旧探索の停止完了を待って、最新の選択へ追従する。
- 停止中に別局面を閲覧しても、実際に新規解析を開始するまでは保持セッションを捨てない。
- 追加予算を使い切ったら停止する。再開には明示的な `start` が必要。
- 同じ局面を解析中の `start` は何もしない（渡した予算は、次に開始・再開するときから使う）。
- 停止の完了を待つ間の `start` は失わない。停止を終えたあと、同じ局面なら再開する。
- パス権は `AnalysisTarget.loadOptions` で渡す。パス権が違えば別の局面として新規解析にする。
- `setVisible(false)` は追従を解除して停止する。再表示だけでは再開しない。離脱は `dispose` で資源を解放する。
- `onInfo` は現在選択中の局面・現在の実行だけを通知する。深さ単位ではまとめない。
- `onFinished` は移動前の対象についても通知する。保存先は通知された対象と sessionId を使い、画面の選択中ノードを使わない。
- `unsupported` は再開 API 未対応。通常探索への切替は呼び出し側の責務であり、続行したようには扱わない。
- `error` ではエンジンを破棄し、再開状態を失効させる。次の開始で初期化し直す。

この段階は状態管理層の実装であり、研究ノート UI・保存 collector・Desktop backend の接続は後続。
